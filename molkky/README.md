# モルック スコア（Ver.1）

モルックの得点を、1台のスマートフォンで全チーム分記録するWebアプリです。ログイン・サーバー不要で、記録は端末のブラウザ内（IndexedDB）に保存されます。PWAとしてホーム画面に追加でき、初回読み込み後はオフラインでも使えます。

## 構成

既存リポジトリ（GitHub Pagesの静的サイト、ビルド工程なし）に合わせ、仕様書推奨のReact＋TypeScript＋Viteではなく、**依存ライブラリなしのES Modules（素のJavaScript）** で実装しています。ビルド不要で、このフォルダをそのまま公開できます。

| ファイル | 役割 |
| --- | --- |
| `js/logic.js` | 得点計算・手番・失格・勝敗・集計（UIから独立した純粋関数） |
| `js/setup.js` | 対戦設定画面のチーム・選手の追加削除 |
| `js/service.js` | 対戦・ゲームの開始／終了、投擲の確定（排他制御・再試行）、取り消し |
| `js/store.js` | 保存層（IndexedDB版・メモリ版）。各操作を1トランザクションで原子的に保存 |
| `js/format.js` | 表示文言、CSV出力 |
| `js/backup.js` | JSONバックアップの出力・検証・取り込み |
| `js/app.js` | 画面の描画と操作 |
| `sw.js` / `manifest.webmanifest` | PWA（オフライン起動） |
| `tests/` | 自動テスト（`node:test`） |

## 起動

ES ModulesとService Workerを使うため、`file://` ではなくHTTPサーバー経由で開いてください。

```sh
cd molkky
npm run serve        # http://localhost:8080/ （npx で http-server を一時利用）
```

Python がある場合は `python -m http.server 8080` でも構いません。

## テスト

Node.js 20 以上が必要です（追加パッケージ不要）。

```sh
cd molkky
npm test
```

得点計算・手番・失格・37点ルール・取り消し・次ゲーム・集計・二重送信・保存失敗と再試行・復元・JSON入出力・CSV（仕様書8章 No.1〜30 のうちUI以外の項目）を確認します。

## ビルド・静的公開

ビルドは不要です。`molkky/` フォルダをそのまま静的ホスティング（GitHub Pages など）に置きます。このリポジトリでは `https://<ユーザー>.github.io/mochiusagi/molkky/` で公開されます。Service Worker を使うため HTTPS（または localhost）で配信してください。

**更新時の注意**：配信ファイルを変更したら `sw.js` の `CACHE_VERSION` を上げてください。新しい版は待機状態になり、ホーム・ゲーム終了・履歴・設定画面に「更新する」が表示されます。ゲーム中に強制リロードすることはありません。

## PWAとしての利用

- iPhone（Safari）：共有ボタン →「ホーム画面に追加」。
- Android（Chrome）：メニュー →「アプリをインストール」または「ホーム画面に追加」。
- 一度オンラインで開けば、以降はオフラインで起動・入力・保存できます。

## 保存・バックアップ

- 確定・取り消し・ゲーム開始・終了のたびに、IndexedDBへ1トランザクションで保存します。保存に成功するまで次の手番へ進みません。失敗時は画面に表示し、「再試行」できます（同じ投擲IDで再送するため重複しません）。
- リロード・タブ終了・端末再起動後も、ホームの「進行中の対戦を再開」で最後に確定した手番から再開できます（未確定の選択は保存しません）。
- 設定画面から全データをJSONで書き出し・取り込みできます。取り込み時は形式・データ版（schemaVersion）・投擲履歴の再計算結果まで検証し、問題があれば何も取り込みません。同じIDの対戦がある場合は上書き確認をします。
- 対戦詳細から、その対戦をCSV（UTF-8 BOM付き）で書き出せます。投擲行（`throw`）とゲーム結果行（`result`）をレコード種別で区別し、名前は数式として実行されないよう先頭の `= + - @` 等を無害化します。
- ブラウザのサイトデータを削除すると記録も消えます。他の端末へは自動で共有されません。

## 対象ルール

日本モルック協会の公式ルールガイドブック・公式スコアシート（確認日：2026-10-19）に基づきます。

- 1本倒れたらその番号、2本以上なら本数を加点。
- ちょうど50点で勝利。50点を超えたら25点に戻す（ミス扱いではなく、連続ミスは0に戻る）。
- 0点（ミス）が同じチームで3回連続したら失格（記録点0）。他チームの投擲を挟んでも、投げる人が変わってもリセットしない。
- 踏み越え（フォルト）は0点ミス扱い。投擲前が37点以上なら25点に戻す。3連続ミス目なら失格を優先。
- 他チームがすべて失格したら、残る1チームの記録点を50として終了（架空の投擲は追加しない）。
- 1ターン1投。各チームに手番が回るたびにチーム内の次の選手が投げる。失格チームは以降スキップ。

**対象外**：投擲順違い、時間超過、ファウル裁定、時間切れ、モルックアウト等の大会の特殊な裁定、複数端末同期、ログイン。大会ルールへの完全対応ではありません。

**集計方針**（本アプリ独自）：完了ゲームの勝利数と、完了ゲームの記録点（失格0点、最後の生存チーム50点）の合計を併記します。未完了・中断ゲームは含めません。総合優勝の自動認定や同点決着戦は行いません。

## 仕様からの変更点・補完事項

| 項目 | 内容 |
| --- | --- |
| 技術構成 | 既存リポジトリ優先の方針により、React＋TS＋Viteではなく依存なしのES Modulesで実装。型チェックの代わりに、計算ロジックの自動テストと取り込み時の構造検証で整合性を担保 |
| Game.status の `ready` | 順番設定中のゲームは保存せず、「この順番で開始」で `inProgress` として作成する。順番設定中にリロードした場合は前ゲームの結果画面（第1ゲームならホーム）に戻る |
| 対戦の保存タイミング | 対戦は第1ゲームの「この順番で開始」時に保存する（仕様「登録情報はゲーム開始時に固定」に合わせた）。順番設定から「チーム設定」に戻って修正できる |
| Game の追加項目 | 保存の重複・競合検出のため `throwCount`（確定済み投擲数）を持つ |
| 対戦名 | 前後空白を除去し最大40文字（チーム名・選手名は仕様どおり20文字） |
| scoreAtLastThrow | そのチームの最後の投擲後の累計（失格チームは0） |
| ミスの取り消し | 取り消した投擲がミス／踏み越えの場合、該当ボタンに「取消前」の印を付けて知らせる |
| 進行中対戦の取り込み | 取り込みにより進行中の対戦が2つになる場合は取り込まない（1台1対戦の制約を守るため） |
| IndexedDB 非対応時 | プライベートブラウズ等で使えない場合はメモリ保存で動作し、記録が残らない旨を表示する |
| 永続ストレージ | 対戦開始時に `navigator.storage.persist()` を要求し、ブラウザによる自動削除を起きにくくする |
| ミス時の確認 | 通常のミスは確認なしで記録（誤入力は「1投戻す」で修正）。踏み越えのみ確認を挟む |
